# Security policy

## Supported versions

Security fixes are applied to the latest release and the `main` branch. Older
releases may be asked to upgrade before a fix is backported.

## Reporting a vulnerability

Please use GitHub's **Report a vulnerability** form on the repository Security
page when it is available. This creates a private advisory that can be discussed
without exposing exploit details.

If private vulnerability reporting is unavailable, open a public issue that only
asks the maintainers for a private contact method. Do not include vulnerability
details, credentials, private keys, access tokens, customer data, or a working
exploit in that issue.

Include the affected version or commit, the security impact, reproduction steps,
and any suggested mitigation in the private report. Use synthetic test data and
revoke any credential that may already have been exposed.

The maintainers will acknowledge the report, investigate it, and coordinate a
fix and disclosure based on its impact. Please allow time for remediation before
publishing details.
